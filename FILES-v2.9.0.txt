========================================================

วิธีใช้
-------
แตกไฟล์ zip นี้ แล้วลากทุกอย่างข้างในไปวางทับที่โฟลเดอร์โปรเจกต์เดิม
(โฟลเดอร์ที่มี package.json อยู่ข้างใน) โครงสร้างข้างในตรงกันอยู่แล้ว
ให้เลือก "แทนที่ไฟล์เดิม" ทั้งหมด

ถ้าอัปโหลดผ่านหน้าเว็บ GitHub ให้ลากไปวางที่:
    kit-stock-system-v1/kit-stock-system-v1/


ต้องทำด้วยมือ 1 อย่าง — ลบโฟลเดอร์ drizzle/
--------------------------------------------
การวางไฟล์ทับไม่ลบไฟล์เก่าให้ จึงต้องลบเอง:

    kit-stock-system-v1/kit-stock-system-v1/drizzle/     <-- ลบทั้งโฟลเดอร์

โฟลเดอร์นี้เป็น migration สาขาที่เลิกใช้แล้ว (auth รุ่น employees)
ถ้าไม่ลบก็ไม่พัง เพราะ wrangler.jsonc ชี้ไปที่ migrations/ แล้ว
แต่ลบออกจะได้ไม่สับสนว่าชุดไหนคือของจริง

หลังวางไฟล์เสร็จ ให้รันตามลำดับนี้
----------------------------------
1) npm install

2) ฐานข้อมูลที่ใช้งานอยู่แล้ว (ของจริงตอนนี้) ต้องรันบรรทัดนี้ครั้งเดียว:

       npm run db:baseline

   ถ้าเป็นฐานข้อมูลใหม่ที่ยังว่างเปล่า ให้ข้ามข้อนี้

3) npm run db:migrate        รัน migration ที่ยังไม่เคยรัน (0010, 0011, 0013)

4) npm run check             typecheck + lint + test ต้องผ่านทั้งหมด

5) npm run deploy

6) เข้าสู่ระบบด้วยรหัส ADMIN — ระบบจะบังคับให้ตั้ง PIN ใหม่ทันที


ข้อควรระวัง
-----------
* ต้องรัน db:baseline ก่อน db:migrate ถ้าเป็นฐานข้อมูลเดิม
  ไม่อย่างนั้น wrangler จะพยายามรัน migration 0000-0009 ซ้ำแล้วพัง
  เพราะไฟล์เก่าเป็น CREATE TABLE และ ALTER TABLE ตรงๆ ไม่ใช่แบบ idempotent

* ต้องรัน migration ก่อน deploy เสมอ
  โค้ดรุ่นนี้ต้องการตาราง app_login_attempts และคอลัมน์ must_change_pin
  ถ้า deploy ก่อน จะเข้าสู่ระบบไม่ได้จนกว่าจะรัน migration

* ข้อมูลเดิมทั้งหมดไม่ถูกแตะ ทดสอบเส้นทางนี้กับฐานจำลองแล้ว
  baseline มาร์ก 11 ไฟล์ แล้ว migrate รันเฉพาะ 0010, 0011, 0013
