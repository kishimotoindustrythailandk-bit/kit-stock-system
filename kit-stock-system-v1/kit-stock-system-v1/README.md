# KIT Delivery Due Control v2.8.5 — Part Excel & Complete Stock Tags

อัปเดต v2.8.5:

- Admin นำเข้าทะเบียน Part จาก Excel ได้ โดยรองรับคอลัมน์ `Part / Material No.`, `Part Name`, `Customer` และ `Max Qty per Box`
- Tag รับเข้า Stock แสดงรูปชิ้นงานและ QR/Barcode ในพื้นที่ด้านบน
- Tag แสดง Customer, Part No./Material, Part Name, Delivery Qty, วันที่ผลิต, Job, จำนวนในกล่อง และเลขกล่อง
- ยังคงแบ่ง Tag ตามจำนวนสูงสุดต่อกล่องอัตโนมัติ และพิมพ์ได้สูงสุด 6 Tag ต่อ A4
- ไม่ต้องรัน SQL เพิ่มจาก v2.8.4

อัปเดต v2.8.4: ในทะเบียน Part ต้องกำหนด **จำนวนสูงสุดต่อกล่อง** และเมื่อสร้าง Tag ให้กรอกจำนวนงานรวมของ Job ระบบจะแบ่งเป็นกล่องและสร้าง Tag จริงให้ทุกกล่องอัตโนมัติ

- กล่องเต็มใช้จำนวนสูงสุดที่กำหนดใน Part และกล่องสุดท้ายเป็นจำนวนเศษ
- แต่ละกล่องมี QR และ Tag ID ไม่ซ้ำกัน พร้อมเลข `กล่อง 1/6`, `2/6` จนครบ
- หน้าพิมพ์ A4 วางได้สูงสุด 6 Tag ต่อหน้า (2 คอลัมน์ × 3 แถว) และขึ้นหน้าใหม่อัตโนมัติเมื่อเกิน 6 กล่อง
- เอาช่อง **Status** ออกจากแบบพิมพ์ Tag แล้ว
- Part ที่นำมาจาก Due แต่ยังมีค่า 0 ต้องให้ Admin กำหนดจำนวนสูงสุดต่อกล่องก่อนสร้าง Tag
- ปุ่มลบ Tag เดิมยังอยู่ และยังลบได้เฉพาะ Tag ที่ยังไม่เคยรับเข้า Stock
- ไม่ต้องรัน SQL เพิ่มสำหรับ v2.8.4

## ตัวอย่างการแบ่งกล่อง

ถ้า Job มี 1,000 ชิ้น และ Part บรรจุได้สูงสุด 180 ชิ้นต่อกล่อง ระบบจะสร้าง 6 Tag:

`180 + 180 + 180 + 180 + 180 + 100`

Tag จะแสดงกล่อง `1/6` ถึง `6/6` และจำนวนจริงของแต่ละกล่อง

อัปเดต v2.8.3: หน้าพิมพ์ A4 หนึ่งหน้าจัดวาง Tag รับงานเข้า Stock จำนวน 6 ดวง (2 คอลัมน์ × 3 แถว) โดยคงรูปชิ้นงานและข้อมูลเดิมทั้งหมด และเพิ่มปุ่มให้ Admin ลบ Tag ที่พิมพ์ผิดหรือไม่ได้ใช้งานได้

- Tag ทั้ง 6 ดวงในหน้าพิมพ์เป็นสำเนาของ Tag Stock เดียวกันและใช้ QR/Tag ID เดียวกัน
- ปุ่ม **ลบ Tag** แสดงเฉพาะ Admin และเฉพาะ Tag สถานะ **รอรับเข้า**
- Tag ที่รับเข้า Stock, จัดงาน หรือขายออกแล้วจะลบไม่ได้ เพื่อรักษายอด Stock, Due และ Traceability
- ไม่ต้องรัน SQL เพิ่มสำหรับ v2.8.3

ขั้นตอน Stock, ข้อมูล QR, การรับเข้า, การจัดงาน, การขายออก, การตัด Stock/Due และหน้าจออื่นคงเดิมจาก v2.8.1

อัปเดต v2.8.1: Admin สามารถค้นหาและลบ Part ที่ยังไม่เคยสร้าง Tag หรือมีประวัติ Stock ได้ ทั้งแบบทีละรายการและลบรายการที่ยังไม่ใช้งานทั้งหมด

ขั้นตอนอัปเกรดและวิธีใช้งาน v2.8 อยู่ในไฟล์ `README-v2.8-TRACEABILITY.txt`

## สิ่งที่ชุดอัปเกรดจะทำ

- เปลี่ยนหน้าเว็บเก่าเป็นระบบ Delivery Due Control ใหม่
- ใช้ Binding เดิมชื่อ `DB` และ `BUCKET`
- เก็บ D1 Database และ R2 Bucket เดิมไว้
- ไม่ลบตารางหรือข้อมูลของระบบ Stock เก่า
- เพิ่มตาราง Due, QR Tag, ผู้ใช้งาน และ Session ที่ระบบใหม่ต้องใช้
- เพิ่ม Due 706 รายการ รวม 69,385 ชิ้น โดยป้องกันข้อมูลซ้ำ
- Admin เพิ่มผู้ใช้งานได้หลายคนจากหน้า **ผู้ใช้งาน**
- กำหนดบทบาท **ผู้จัดงาน** (สแกนรับเข้า) หรือ **ผู้ตรวจงาน** (สแกนส่งออกและตัด Due)
- ตั้ง/รีเซ็ต PIN 6 หลัก เปิดใช้หรือระงับบัญชีได้จากหน้าเว็บ
- PIN ของผู้ใช้ใหม่จัดเก็บแบบ PBKDF2 Hash ไม่เก็บเป็นข้อความปกติ
- สแกนแล้วบันทึกและแสดงข้อมูลทันที ไม่ต้องกดปุ่มตรวจสอบ Tag
- แสดงรูปชิ้นงานทันทีพร้อมข้อมูล Tag/Due หลังสแกน ทั้งรับเข้าและส่งออก
- Admin ผูกรูป JPG, PNG หรือ WebP กับ Material / Part No. ได้จากหน้า **ตั้งค่า**
- เก็บไฟล์รูปใน R2 เดิม และเก็บรายการเชื่อม Material ใน D1 เดิม
- หน้า **รายงาน** ส่งออกข้อมูลตามตัวกรองปัจจุบันได้เป็น Excel, CSV และ PDF
- Excel มีชีตสรุปและชีตรายละเอียด Due ส่วน PDF จัดหน้าแนวนอนสำหรับพิมพ์หรือบันทึกเป็นไฟล์
- Admin ลบข้อมูล Excel เป็นรายชุดได้จากหน้า **แผนส่งงาน (Due) > ประวัตินำเข้า Excel**
- ก่อนลบมีหน้าต่างยืนยัน และหากชุดนั้นมีประวัติรับเข้า/ส่งออก ระบบจะเตือนซ้ำพร้อมจำนวนรายการ
- การลบกระทบเฉพาะชุดไฟล์ที่เลือก ไม่ลบผู้ใช้งาน รูปชิ้นงาน หรือ Due จากไฟล์ชุดอื่น
- หน้าโทรศัพท์จัดวางใหม่ให้อ่านง่ายโดยไม่ต้องซูมหรือเลื่อนตารางซ้าย–ขวา
- ตาราง Due, รายการสแกน, รายงาน และผู้ใช้งานเปลี่ยนเป็นการ์ดบนหน้าจอเล็ก
- มีเมนูหลักด้านล่างสำหรับใช้งานด้วยนิ้วโป้ง และเปิดเมนูทั้งหมดจากปุ่ม **เมนู**
- หน้าสแกนย่อกรอบกล้องให้พอดีจอ ปุ่มสแกนมีขนาดใหญ่ และหลังสแกนจะเลื่อนไปยังรูปชิ้นงานกับยอด Due อัตโนมัติ
- ตัวกรองบนมือถือพับเก็บได้เพื่อเพิ่มพื้นที่แสดงข้อมูล

## ถ้าอัปโหลดผ่าน GitHub ตามภาพ

Repository ของคุณคือ `kishimotoindustrythailandk-bit/kit-stock-system`

1. แตก ZIP นี้บนคอมพิวเตอร์
2. เข้าโฟลเดอร์ชั้นในสุดของระบบเก่าที่มี `app`, `db`, `public`, `worker` และ `package.json`
3. วางไฟล์จาก ZIP ทับโฟลเดอร์นั้น และเลือก **Replace files**
4. อย่าสร้างโฟลเดอร์ `kit-stock-system-v1` ซ้อนเพิ่มอีกชั้น
5. Upload/Commit ไฟล์ที่แก้ไขกลับไปยังตำแหน่งเดิมใน GitHub
6. Cloudflare จะ Build และ Deploy ทับ Worker `kit-stock-system` โดย URL เดิมไม่เปลี่ยน

หากระบบปัจจุบันเป็น **v2.3, v2.4 หรือ v2.5 อยู่แล้ว ไม่ต้องรัน SQL เพิ่ม** สำหรับ v2.6 นี้ ให้วางไฟล์ทับและ Commit ได้เลย

เฉพาะกรณีอัปเกรดจากเวอร์ชันก่อน v2.3 เท่านั้น หลังโค้ด Deploy แล้วให้รัน `database-upgrade-v2.2-users-scan.sql` และ `database-upgrade-v2.3-part-images.sql` อย่างละหนึ่งครั้ง (ไฟล์ใช้ `IF NOT EXISTS` และไม่ลบข้อมูลเดิม)

## วิธีแนะนำ: อัปเกรดจากคอมพิวเตอร์ Windows

วิธีนี้จะอัปเกรด D1 และ Deploy ให้ครบอัตโนมัติ

1. สำรองโฟลเดอร์ระบบเก่าไว้หนึ่งชุด
2. วางไฟล์จาก ZIP ทับโฟลเดอร์ระบบเก่า
3. ดับเบิลคลิก `INSTALL-WINDOWS.bat`
4. Login Cloudflare เมื่อเบราว์เซอร์เปิด
5. ตั้ง PIN ใหม่สำหรับรหัสพนักงาน `ADMIN`

ตัวติดตั้งจะใช้ Binding เดิม ไม่สร้าง D1 หรือ R2 ใหม่

## อัปเกรดด้วยคำสั่งเอง

```bash
npm install
npx wrangler login
npm run db:upgrade
npm run db:upgrade:v22
npm run db:upgrade:v23
npm run deploy
npx wrangler secret put INITIAL_ADMIN_PIN --config dist/server/wrangler.json
```

## เข้าสู่ระบบใหม่

- รหัสพนักงาน: `ADMIN`
- PIN: ค่าที่ตั้งตอนใช้คำสั่ง `INITIAL_ADMIN_PIN`

จากนั้นเข้าเมนู **ผู้ใช้งาน** แล้วกด **เพิ่มผู้ใช้งาน**:

1. ระบุรหัสพนักงาน ชื่อ และ PIN 6 หลัก
2. เลือก `ผู้จัดงาน — สแกนรับเข้า` หรือ `ผู้ตรวจงาน — สแกนส่งออก/ตัด Due`
3. ผู้ใช้เข้าสู่ระบบด้วยรหัสพนักงานและ PIN ของตัวเองได้ทันที
4. หากต้องหยุดสิทธิ์ ให้ Admin กด **ระงับ** ระบบจะยกเลิก Session ของคนนั้นทันที

## เพิ่มรูปชิ้นงานให้แสดงตอนสแกน

1. เข้าระบบด้วย Admin และเปิดเมนู **ตั้งค่า**
2. ที่หัวข้อ **รูปชิ้นงานสำหรับหน้าสแกน** ระบุ Material / Part No.
3. เลือกรูป JPG, PNG หรือ WebP ขนาดไม่เกิน 5 MB แล้วกด **บันทึกรูปชิ้นงาน**
4. เมื่อผู้จัดงานหรือผู้ตรวจงานสแกน Tag ที่มี Material เดียวกัน รูปจะแสดงทันทีพร้อมข้อมูล Due
5. หากยังไม่มีรูป ระบบจะแสดงช่องสำรอง “ยังไม่มีรูป” โดยการสแกนและตัดยอดยังทำงานตามปกติ

## สำรองข้อมูลก่อนอัปเกรด

แนะนำให้เปิด Cloudflare > Storage & databases > D1 > ฐานข้อมูลเดิม > Backups และสร้าง Backup ก่อน แม้ไฟล์อัปเกรดนี้ไม่มีคำสั่งลบข้อมูล

## ไฟล์ข้อมูลต้นฉบับ

โฟลเดอร์ `source-files` มี Excel ต้นทางสองไฟล์และ PDF Tag ตัวอย่าง ไฟล์ PDF ไม่ถูกนำไปตัดยอดอัตโนมัติ
